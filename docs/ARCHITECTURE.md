# 架构说明

## 一句话

用一份 JSON 描述的直线程序，驱动 MoonBit 的核心原语在多个后端上执行，
把每一步的结果规范化成纯 ASCII 转录，逐位比对、定位、收缩。

## 为什么是「直线程序」

MoonDiff 的程序模型不是任意 AST，而是**寄存器化的直线指令序列**。这不是简化，
而是三个设计约束同时指向的结论：

1. **可判定的收缩**。直线程序没有控制流，每条指令的输入只由前驱决定。
   删掉一条不影响分歧的指令，其余指令读到的值一个字节都不会变，
   因此「删除是否安全」不需要重新执行后端就能判定。
   这让收缩从 O(n log n) 次编译执行降为一次反向可达性分析。
2. **可归因**。每条指令对应一个明确的核心原语（整数除法、浮点开方、字符串比较……），
   差异一出现就能立刻说清「是哪个原语出的问题」，而不是「某段代码算错了」。
3. **可复现**。没有控制流就没有路径爆炸，同一份 JSON 在任何后端、任何时间
   都必须给出同一份转录。

## 数据流

```
             ┌────────────┐
  seed ────► │  gen       │ ──► 程序 JSON（单行、纯 ASCII）
             └────────────┘
                     │
        ┌────────────┴────────────┐
        ▼            ▼            ▼            ▼
   ┌────────┐  ┌─────────┐  ┌────────┐  ┌────────┐
   │ wasm   │  │ wasm-gc │  │   js   │  │ native │   ← 同一份源码，四个后端
   └────────┘  └─────────┘  └────────┘  └────────┘
        │            │            │            │
        └────────────┴─────┬──────┴────────────┘
                           ▼
                    ┌─────────────┐
                    │  transcript │  转录：#step op rDst <canon>
                    └─────────────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │  diff    │ │  matrix  │ │  shrink  │
        └──────────┘ └──────────┘ └──────────┘
                           │
                           ▼
                    ┌─────────────┐
                    │   oracle    │  裁定：谁违反规范
                    └─────────────┘
```

裁定需要两样东西：**规范侧期望值**与**现场证据**。
前者来自可引用的文档条款（core 的 `Int` 回绕语义、IEEE 754 的 NaN 条款），
后者来自转录。两者都有才下结论，缺任一条就落 `Undetermined`——
这个约束保证了「裁定」不同于「猜测」。

## 包职责

| 包 | 职责 | 关键约束 |
| --- | --- | --- |
| `src/core` | 值模型、规范编码、比较档位、转录比对 | 纯函数，不做 I/O |
| `src/spec` | 程序模型（54 条原语）、JSON 编解码 | 64 位整数用十进制字符串、浮点用位串 |
| `src/exec` | 参照解释器、覆盖统计 | 不做算术，只转发给宿主原语 |
| `src/gen` | 确定性随机源、生成、变异、语料库 | 同种子同序列，与后端无关 |
| `src/shrink` | 依赖闭包、收缩、伪代码渲染 | 删除必须是语义空操作 |
| `src/oracle` | 规范裁定：违规方 / 规范值 / 依据 | 只在有规范依据时下结论，否则 `Undetermined` |
| `src/report` | 矩阵、差异摘要 | 输出纯 ASCII |
| `cmd/driver` | 四后端共用的执行器、常量折叠电池 | 只读 argv，只写 stdout |
| `cmd/moondiff` | CLI 与手工探针 | 同上 |

## 转录格式

```
#<step> <opname> r<dst> <canonical-value>
```

值编码：

| 类型 | 编码 | 例 |
| --- | --- | --- |
| unit | `_` | `_` |
| int | `i<十进制>` | `i-2147483648` |
| i64 | `l<十进制>` | `l-9223372036854775808` |
| f64 | `f<16 位十六进制位模式>` `\|<格式化>` | `fff8000000000000\|NaN` |
| string | `s<码元数>/<码点数>:"<转义>"` | `s4/3:"a\u{4e2d}\u{1f600}"` |
| array | `a<长度>[<元素>]` | `a3[1,2,3]` |

最后一行为哨兵 `#end <n>`。**没有哨兵就说明该后端在途中终止**，
此时转录可能被整体丢弃（缓冲区未刷出），长度不能当作执行步数。

## 三个不能妥协的约束

1. **工具自身必须四后端一致**。所以：不读文件、不读环境、不 spawn 子进程、
   不用宿主随机源、不依赖宿主哈希、不用浮点格式化做比较依据（只用位模式）。
2. **编解码不能丢位**。JSON 数字是 f64，`9223372036854775807` 过一遍就会失真，
   而失真恰好会把要抓的差异抹平。因此整数走字符串、浮点走位串。
3. **报告必须可被机器读**。纯 ASCII、固定列、无颜色转义，便于 CI 直接 diff。

## 裁定的三条设计约束

1. **先判硬缺陷，再判自由度**。顺序反了，真缺陷会被「实现自由度」这个筐吃掉。
   `adjudicate` 的调用顺序被刻意固定：`int-div` → `nan-sign` → `float-format` → `Undetermined`。
2. **只认常量操作数**。裁定需要知道操作数才能说「这里溢出了」。
   操作数来自运行期计算时返回 `Undetermined`，不去猜。
3. **trap 场景不信任步号**。后端终止时转录被整体丢弃，步号归零。
   此时改走 `find_static_violation` 按程序结构定位，
   矩阵里的 `step` 也显示 `?` 而不是 `0`——宁可显示「不知道」，也不显示错误的确定值。
