# 已观测到的跨后端差异

记录时间：2026-11-12（裁定机制与结论更新于 2026-11-13）
工具链：`moon 0.1.20261020 (2284bd2 2026-10-20)`，核心库 `moonbitlang/core 0.10.16`
本机可用后端：`wasm` / `wasm-gc` / `js`（本机未装 MSVC Build Tools，`native` 由 CI 覆盖）

> 本文的每条结论都可以用仓库内的命令复现，并已写入回归基线 `tests/expected.txt`。
> 文中判定只针对上述工具链版本；工具链升级后若行为改变，基线会立刻报警。

---

## 判定分三级，不能混为一谈

差分工具最容易犯的错是把「不一样」直接说成「bug」。本项目的每条发现都落到以下三档之一：

| 标签 | 含义 | 处置 |
| --- | --- | --- |
| `SPEC-VIOLATION` | 有可引用的规范，且某后端违反它 | 缺陷，应上报并修复 |
| `IMPLEMENTATION-FREEDOM` | 规范未作规定，多种结果都合法 | 不是缺陷，但需在工程上归一化 |
| `UNDETERMINED` | 缺规范依据或缺操作数，判不了 | 明确承认判不了，不猜 |

这个分级是 `src/oracle` 的实现对象，也是它能被称为「裁定」而不只是「比对」的原因。

## 发现 1：`INT_MIN / -1` —— 违反语言规范

**裁定：`SPEC-VIOLATION`，违规方 `wasm`、`wasm-gc`。**

### 现象

```
-2147483648 / -1
  wasm / wasm-gc -> RuntimeError: divide result unrepresentable（进程终止）
  js             -> -2147483648（回绕）
```

### 依据

MoonBit 核心库文档对 `Int` 的规定：32 位整数、二补数运算、溢出按回绕处理，
文档示例即 `2147483647 + 1 == -2147483648`。同一规则下 `INT_MIN / -1`
的规范结果应当是 `INT_MIN` 本身，而不是终止进程。

补一条排除项：除数为 0 的情形不在此列——本项目在规格里把整数除零显式定义为 0，
不会被这一条覆盖。

### 为什么这条比「取到错值」更严重

这是**终止性差异**，不是取值差异：wasm 侧进程直接死掉，连已经打印的转录都被丢弃。
调用方拿到的是崩溃，不是错误值；在没有调试器的环境里，崩溃点比错值难定位得多。

### 最小复现（3 条指令）

```json
{"seed":0,"profile":"strict","ops":[["iset",0,-2147483648],["iset",1,-1],["idiv",2,0,1]]}
```

```bash
bash scripts/matrix.sh examples/min-div-overflow.json
```

矩阵末段会给出裁定：违规方 `wasm, wasm-gc`，规范值 `i-2147483648`，并附上依据。

### 工具上的两个连带结论

1. **转录必须有结束哨兵**。没有 `#end <n>` 就说明后端在途中终止，此时已缓冲的输出
   可能整体丢失，转录长度不能当作执行步数。
2. **trap 时步号不可信**。所以矩阵里 `step` 显示 `?` 而不是 `0`，
   真正的步号由 `scripts/localize.py` 前缀二分确定，或由
   `src/oracle` 的静态扫描（`find_static_violation`）直接指出。
   这两条都是被这条发现逼出来的设计。

## 发现 2：常量折叠后 NaN 的符号位 —— 实现自由度

**裁定：`IMPLEMENTATION-FREEDOM`，不构成缺陷。**

### 现象

```
(0.0 / 0.0).reinterpret_as_int64()
  wasm / wasm-gc -> 0xFFF8000000000000   （负 quiet NaN）
  js             -> 0x7FF8000000000000   （正 quiet NaN）
```

### 依据

IEEE 754-2019 §6.2.3 不规定 NaN 的符号位：正 quiet NaN 与负 quiet NaN 都是合法结果。
因此「两个后端给出不同符号」本身不构成缺陷，把它写成 bug 属于过度断言。

### 为什么仍然值得记录

差异只出现在**编译期常量折叠**：当 `0.0 / 0.0` 是运行期求值时，三个后端都得到
`0xFFF8000000000000`，完全一致。也就是说，同一个表达式在「折叠」与「不折叠」两条
编译路径上会给出不同位模式。

对依赖位序列化的代码——哈希、缓存键、黄金文件比对、跨进程缓存——这会造成
平台相关行为。工程上的正确做法是显式归一化 NaN（本项目在 `semantic` 比较档里折叠掉），
而不是要求各后端统一符号位。

### 复现

```bash
for t in wasm wasm-gc js; do moon run cmd/driver --target $t -- literals | head -1; done
```

24 条常量折叠探针里，**23 条三个后端一致，1 条（`L0 nan_div`）不同**。
这条计入回归基线，形如：

```
literals:wasm-vs-js        diff-lines=2
```

（`diff` 输出的一删一增两行；它是基线内的已知量，不是新增问题。）

## 观察 3：`@env.args()` 在 js 上多两个元素

**归类：实现差异，文档已写明，属可预期的平台差异。**

```
moon run ... --target wasm -- alpha "b c"   -> argc = 3
moon run ... --target js   -- alpha "b c"   -> argc = 4
```

js 后端把 `node` 可执行文件与脚本路径也放进了 argv。这对「按 `args[0]` 当作程序名」
的代码是一个陷阱。

**本项目的应对**：`cmd/driver` 与 `cmd/moondiff` 取 argv 的末位元素或扫描子命令名，
不假设固定下标，从而在四个后端上都能取到正确参数。这一条已在 `scripts/selfcheck.sh`
里被间接验证——四个后端跑同一命令，输出必须逐字节一致。

## 尚未覆盖的部分

- **`native` 后端**：本机无 MSVC Build Tools，本地矩阵只有 3 列。
  仓库 CI 在 `ubuntu-latest` 上跑满四后端（Linux 上 native 只需 gcc），
  并用「输出必须是 24 条折叠结果」显式断言 native 真的执行了，而不是被记为 PASS。
- **大整数与高精度小数**：当前原语集只覆盖 32/64 位整数与 f64。
- **并发与 GC 时机**：属非确定性维度，不在本版本差分范围内。
- **未定性的差异**：若 `regress.sh` 出现基线外的新标签，裁定为 `UNDETERMINED` 时
  必须人工对照规范确认，不得直接放宽基线。

---

## 处置原则

1. **发现的缺陷不自行「修掉」**。差分工具的职责是报告与判定，不是掩盖。
   在 `src/exec` 里加保护让 trap 消失，等于把工具变成安慰剂。
2. **已知差异进基线**。`tests/expected.txt` 记录每一条已定性的结论，
   CI 只对**新增**差异报警。这样既不反复刷屏，也不静默放过。
3. **改动基线必须写明理由**。基线文件里已注明：静默放宽基线等于掩盖差异。
4. **可以上报的缺陷照实上报**。发现 1 的最小复现与外部分析已足以提交上游 issue，
   但上报与否、以何名义上报，由项目作者决定，工具本身不代替人做这个动作。
